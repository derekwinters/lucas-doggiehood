Confirmation dialog

A small, reusable centered card over a dimmed scene that asks the player to confirm one action. The title and body text are dynamic — supplied by whatever opened it — and the two actions are always No / Yes (kept literal for young players). When the action costs coins, the Yes button carries a coin + amount so the price is unmistakable. First consumer: the map-expansion zone unlock (#343), shown here with placeholder copy.

Shown 1:1 at the true 1920×1200 reference. The title/body copy and the 100-coin cost are placeholders — real text and amount are passed in by the caller.

Regions

Scrim (full-screen dim; tapping it = cancel = No) · Title (dynamic) · Body (dynamic) · Action row (two equal-width pill buttons).

Dynamic text: title and body are set by the caller; the card grows vertically with the body length. Messages are meant to be short (one question + a sentence), so no scrolling — keep copy tight.

Buttons: always No (neutral/cream, left, the safe default) and Yes (positive/leaf, right) — labels stay literal Yes/No for a kids' game. The confirm is always leaf. When the action has a coin cost, Yes shows a coin token + amount after the word (a `CostCoinDiameterPx` gold token + tabular number, `IconGapPx` from the label); a cost-free confirmation shows just “Yes”. Both reuse the shared PillButton (#173).

Disabled Yes (#690): when the caller says the spend can't succeed — the wallet won't cover it — the dialog still opens, but Yes takes the shared Disabled role tint (#D8D2C6) and is non-interactable, the same greying an unaffordable quest gift pill (#186) and house-upgrade button (#294) already use. The cost token stays on Yes so the player sees the price they're short of, and No + the scrim still dismiss — greying the confirm never greys the way out (#329). Affordability is resolved once, at open (matching the quest pills), and it comes from Core — the house build passes HouseBuildOffer.IsAffordable, never a Unity-side wallet comparison. Invariant: a spend button is never pressable when the spend cannot succeed. Nothing about the layout changes.

Reusable: one overlay any screen raises. First use is the zone-unlock confirm (#343, tap the lock icon → this dialog with the zone cost on Yes → TryUnlockNextZone()); later spend confirms (house build/upgrade) reuse it by passing their own copy + amount.
