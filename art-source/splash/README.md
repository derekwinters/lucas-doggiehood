# art-source/splash — the splash art, rebuilt as separate layers

The game's splash image (`Assets/Art/Splash/cover-art.png`, from #120 / #90) is one
flattened 2816×1536 raster. This folder rebuilds it as separate, reusable layers
(#841): the **DOGGIEHOOD title text**, the **background and environment**, and the **dogs**. Nothing here is used by the game;
nothing under `Assets/` changes.

| Layer | Status | How it is made |
|---|---|---|
| Title text | approved (paw-in-the-O option A) | vector rebuild, `build_title.py` |
| Sky, sun, clouds, street, houses (far / left / right), trees, props | hand-built clean objects — awaiting Derek's review | authored geometric primitives, `build_env.py` + `env_shapes.py` (written by `build_scene.py`); the previous trace (`--env traced`) and the first hand-built scene (`--env hand`) stay available |
| Each dog (corgi, schnauzer, golden retriever, dalmatian, puppy) and their shadows | traced — awaiting Derek's review | vector trace of the original, `trace_dogs.py` (written by `build_scene.py`); the earlier hand-drawn dogs stay available in `build_dogs.py` (`--dogs hand`) |

## What is in git

Only the sources and the key images are committed; everything else is regenerated by the
build or kept outside git (`.gitignore` in this folder ignores every PNG except the
committed ones, and all of `review/`).

| Committed | Generated, not committed |
|---|---|
| The scripts (`*.py`), `fonts/Fredoka-Variable.ttf` and `fonts/OFL.txt`, this README | `title/doggiehood-title-preview.png`, `title/doggiehood-title-flat-preview.png` |
| Every SVG: `title/`, `scene/` (layers and composite), `objects/`, `dogs/` | `objects/<id>.png` (every object PNG; the object SVGs stay committed) |
| `title/doggiehood-title-6000.png` and `title/doggiehood-title-flat-6000.png` | Everything in `review/` |
| `scene/composite.png` and every full-frame layer PNG `scene/<layer>.png` (5632 × 3072, dog layers included) | |
| The standalone dog PNGs `dogs/<dog>.png` | |

Regenerate the rest with:

```sh
python3 art-source/splash/build_title.py   # title previews and the title review images
python3 art-source/splash/build_scene.py   # objects/*.png and the scene, dog and environment review images
```

The **review images** — the ones the build writes and the ones made by hand for a single pass
("not rebuilt by the build" below) — live in the project's shared folder
(`splash-layers/final-review/`, with the object PNGs beside them), not in git. The PNGs there
carry an extra provenance chunk the shared folder adds on upload; their pixels and every
other byte match what the build wrote. `review/env-traced-composite.png` (the previous traced
scene) is one of them: copy it into `review/` to get the "traced" column of
`review/env-built-vs-original.png`; without it that sheet shows the original and the built
scene only.

The byte-identical self-checks do not depend on what is committed: each script builds once,
takes the SHA-256 of its output files (layers, objects, dogs and, unless
`--no-review`, the review images), builds again from scratch in the same run and compares.
So they prove reproducibility on a fresh clone, where the generated files do not exist yet.
To check that the committed images are up to date, run the build and look at `git status`.

## Title text

The title is **rebuilt as vector art**, not cut out of the raster: a cut-out would be
capped at the source resolution (~1,700 px wide) and keep sky-coloured fringing. The
vector prints at any size.

### Layers in `doggiehood-title.svg` (bottom to top)

| id / layer | What it draws |
|---|---|
| `drop-shadow` | Soft navy shadow under the word (22% opacity). Hide it for printing on dark fabric if the printer can't do halftones. |

### Paw inside the first "O" — options (Derek chose A)

In review, the paw inside the first "O" read as a surprised face to some eyes. The
options are built from one script via `--o-paw`. Derek chose **A** (the current paw),
which is the committed default; the other options' previews stay in `review/` for reference.

| Option | What it is |
|---|---|
| A | Current paw (reference). |
| B | Same paw rotated 28°. |
| C | Reshaped: wider heart/triangle pad, toes arched close to it. |
| D | Rotated and reshaped (B + C). |
| E | No paw in the O — it looks like the other O's; the paw stays on the "i". |

`python3 art-source/splash/build_title.py --o-paw D` exports the chosen option (then
make it the default by setting `O_PAW_DEFAULT`).

Effects are SVG strokes on the letter paths (round joins), so they stay editable. A
cutter or RIP that needs filled outlines only: Inkscape *Path → Stroke to Path*, or
Illustrator *Object → Expand*.

### Font and licence

Letterforms are from **Fredoka** (The Fredoka Project Authors), SemiBold instance
(`wght` 600, `wdth` 100) of the variable font, licensed under the **SIL Open Font
License 1.1** — see `fonts/OFL.txt`. The OFL allows using the font in artwork, including
printed and sold merchandise; the font file is committed here so the build is
reproducible. Fredoka was picked after rendering a dozen open-licensed rounded display
fonts (Baloo 2, Lilita One, Titan One, Sniglet, Chewy, Luckiest Guy, Coiny, Nunito,
Grandstander, DynaPuff, …) against the original: its round D/O, the G's inward bar and
the short lowercase-style dotless i are the closest match. The extra chunkiness, rim,
outline and bounce are added by the build script.

### Rebuilding

```sh
pip install fonttools cairosvg pillow numpy
python3 art-source/splash/build_title.py
```

The script lays the letters out in the original image's pixel space (so the rebuild can
be compared directly against the raster), writes both SVGs, renders the PNGs with
CairoSVG, writes the review images (they read the original from `Assets/Art/Splash/`,
read-only), and then **self-checks**:

- the print PNGs are at least 6000 px wide;
- nothing touches the image edge (border alpha is 0) and every visible pixel touching the
  transparent background is the outline navy — i.e. no fringe;
- no background is enclosed inside the outline (no pinholes between letters);
- the flat version uses at most 4 colours;
- every highlight pixel sits on fully opaque letter (or i-dot paw) fill, there is
  exactly one highlight per letter, and the clip never visibly cuts an oval (the
  clipped and unclipped highlight renders match);
- across the width of the i's stem there is a gap of navy outline (≥ 5 px) between
  the i-dot paw and the stem;
- building a second time produces byte-identical files.

All tuning lives in named constants at the top of `build_title.py` (letter positions,
arch, outline/rim thickness, colours, paw sizes). Byte-identical output holds for a given
toolchain; the committed files were built with Python 3.13, fontTools 4.68, CairoSVG 2.9
(cairo 1.18), Pillow 13 and NumPy 2.5 — a different cairo version may anti-alias
slightly differently.

## Background and environment (`scene/`, `objects/`)

Everything in the splash except the title and the dogs. Since Derek's review of the traced
version ("a lot of inconsistent surfaces and edges … create each object separately … the
complete object even if it's covered today"), every environment object is **hand-built as
clean vector geometry** (`build_env.py`, geometry in `env_shapes.py`): each house, tree,
bush, fence, mailbox, flower, toy, cloud, the street pieces and the sun is its
own object, made of crisp primitives, and complete even where the dogs, the title or a
nearer object hide it. The design is the original's (shapes, proportions and colours are
measured on it), except where Derek chose otherwise: the clouds are round, and the
original's sparkle in the bottom-right corner is not drawn (see below).

All layers share one full-frame canvas in the original's pixel space
(`viewBox="0 0 2816 1536"`), so they stack straight back together.

### How the environment is built

1. **Authored shapes.** Every object is a list of faces, back to front: polygons with
   straight edges, plus circles, ellipses and circular arcs only where the original is round
   (the sun, the clouds' lobes, flower petals, the mailbox tops, the rounded fence pickets,
   the toys' spots). Corners were measured on the original (zoomed crops with a
   pixel grid, and colour-run scans along rows and columns); the earlier traces and masks
   were used only as a reference for where corners go.
   **Invariant: no traced, VTracer or bitmap-derived path appears in any environment layer;
   every edge is an authored shape.**
2. **Flat colours measured from the original.** Each face is one flat colour (or, on large
   faces — walls, roofs, the ground — one linear gradient; the road, sidewalks and
   lawns a vertical gradient). The colour is the median of the original's pixels that show
   that face: inside it, not hidden by a dog, the title, or any face drawn above it, with
   outliers dropped. A face the original hides entirely says where its colour comes from
   (another face, or a colour). Some faces are measured at a chosen clean spot of their
   surface instead (`at`), where trees or haze muddle the face itself (the far houses'
   walls, roofs, barge boards and glass). The far trees' facets come in three tones, each
   measured on the original: the crown's pixels (other hues dropped) are ranked by
   lightness, and the light, mid and dark tones are the medians of the upper, middle and
   lower slices (`of=` + `q=` in `build_env.py`).
3. **Stacking.** Objects go into the layers in the original's draw order. An object that
   stands behind something drawn earlier (the tree behind the red house, the far tree
   behind the far yellow house, the treeline behind the far houses, the yellow house's
   fence behind its steps) is clipped in its layer by that object's outline; its standalone
   file is the whole object.
4. **Sky and sun** stay a vertical gradient and a radial glow fitted to the original's open
   sky (the pixels no object covers). Since our clouds are round where the original's are
   blocky, it is the original's cloud outlines (`ORIGINAL_CLOUDS` in `env_shapes.py`) that
   are kept out of that fit, so the sky and sun are unchanged by the cloud shapes.

### Sidewalk joints, front paths and mailboxes

Derek: "The sidewalk needs more separating lines, and it looks like some houses don't have
sidewalks and or mailboxes." The original shows only two expansion joints on each sidewalk,
and not every house had a front path and a mailbox, so this pass adds them (all in
`env_shapes.py`; see `review/sidewalk-mailbox-before-after.png` and `review/new-objects-sheet.png`).

> **How this changed (#841).** The environment used to draw only what the original shows: two
> joints per sidewalk ("no paths or joints invented"), and paths and mailboxes for some houses
> only. Now every sidewalk carries a full series of joints from the foreground to the far end, and
> every house has a front path and a mailbox, because Derek asked for them.

- **Joints.** A joint runs straight across the sidewalk, square to the street, so in one-point
  perspective it is a horizontal band from edge to edge. The slabs are all the same size, so the
  joints are evenly spaced along the street: on screen, `1 / (y - y_h)` steps by the same amount
  from joint to joint, where `y_h` is the height at which that sidewalk's two edges meet. As the
  sidewalks are drawn (measured on the original), their edges meet near (1470, 606) on the left
  and (1454, 580) on the right — the street's vanishing point is about x 1470, but higher than the
  road's visible end at y 700 (`MB_VP`), so the joints are spaced toward the point the edges
  really converge on. The original's two joints on each side (`joint-1`, `joint-2`, kept as they
  were, measured) are one slab apart and set the step; the series continues from them to where
  the paving starts (y 713): 26 joints on the left, 22 on the right. Each new joint takes
  `joint-1`'s measured colour, and its drawn thickness shrinks with distance in proportion, so the
  farthest are hairlines. **Invariant: every sidewalk joint is horizontal, spans the sidewalk's
  full width and lies on the one-slab series its sidewalk's two original joints define.** The far

### Street layout invariants

Derek: "The pink house on the right, 3rd back, mailbox looks like it's on the path. Make sure all
the paths, mailboxes, and front steps, are aligned correctly." The pass above placed each mailbox
by height on screen alone, and the steps and paths came from the original as measured, so some
steps sat beside their doors, some far mailboxes stood on a path or in front of another house's
door, and the far yellow house had no steps at all.

> **How the spec is changing (#841).** It used to say only that every house has a path and a
> mailbox, each mailbox "matched to the house whose front is at its depth … not always the house
> it stands in front of". It now states how a house's door, steps, path and mailbox line up, as
> the rules below, and every build checks them from the geometry. Placing by height on screen
> alone let a mailbox sit on a path or in front of the wrong house; the rules rule that out.

Each house's lot is one row of `STREET` in `env_shapes.py` (its door, steps, path and mailbox), and
`check_street()` in `build_env.py` checks every rule for all eleven houses before anything is
rendered; the build stops on the first one broken. Depths are measured as on the sidewalk: a
ground line square to the street is horizontal on screen, and one slab of depth is one step of
`1 / (y - y_h)` in the joint series (see **Joints** above).

- **street-1 — Invariant: every house's front steps sit centred on its front door.** The centre
  of the steps' face toward the viewer (the near houses' stepped side face, the far houses'
  treads and risers) is within 5 % of the door's width of the door frame's centre, and the door's
  bottom rests on the steps (between their top and their foot, within 1 px).
- **street-2 — Invariant: a house's front path runs straight from the foot of its steps to the
  sidewalk, in perspective, and meets the sidewalk at a joint line.** The steps' foot lies on the
  path's far edge from end to end; from there the path's far and near edges are horizontal (one
  depth, square to the street) to the sidewalk; its street end follows the sidewalk's lawn edge;
  and its joint line covers exactly that end.
- **street-3 — Invariant: each house has exactly one mailbox**, and every mailbox belongs to one
  house.
- **street-4 — Invariant: every mailbox stands by one rule in ground space: on the lawn, the
  same distance behind the sidewalk's lawn edge and the same distance beside its own path, on
  the side of the path nearer the viewer, on both sides of the street.** Its post foot's centre

### House perspective invariants

Derek, marking up the green house's struck-through sill, flower-box and trim bands: "a lot of the
angles on the houses are wrong. Like the window flower boxes look like they are angled differently
than the house is angled. Check all the houses." The houses kept the original's painted angles:
trim bands, gable windows, roof ridges and the steps' edges tilted a few degrees each, and the
flower boxes stuck out toward the street, so a box and the wall it hangs on disagreed.

> **How the spec is changing (#841).** It used to say only that every shape is measured on the
> original (its corners where the original paints them). It now says that every house follows one
> perspective, as the rules below, and every build checks every edge of every house against them.
> The original's tilts are painted, not perspective: taken as measured, a flower box and its wall
> disagree, which is what Derek saw.

The scene is **one-point perspective**. Its vanishing points are where each sidewalk's two edges
meet (`meet()` in `env_shapes.py`): **(1469.5, 606.0) on the left** and **(1453.8, 579.7) on the
right**, the same points the joints, paths and mailboxes use. Each house face carries its `plane`
(`front` unless it says otherwise), and `check_perspective()` in `build_env.py` checks every straight
edge of every face of all eleven houses, near and far, both sides, before anything renders. An edge
within 35° of horizontal is a horizontal feature, one steeper than 84° a vertical, and anything
between, on a wall, a rake (a gable's edge, a roof's hip, a chimney meeting the roof).

- **persp-1 — Invariant: every wall face is either a front face (facing the street, parallel to
  the picture plane) or a side face (receding toward the vanishing point).**
- **persp-2 — Invariant: on a front face every horizontal feature is exactly horizontal** —
  sills, flower boxes, trim bands, eaves, fascia, roof ridges, window and door heads, the steps'
  edges and the foundation lines (within 0.5°).
- **persp-3 — Invariant: on a side face every horizontal feature lies on a line through its side's
  vanishing point** (within 0.5°).
- **persp-4 — Invariant: verticals are vertical**, on both (within 0.5°).
- **persp-5 — Invariant: an attached feature takes the plane of the wall it is on**: a sill, a
  flower box or a trim band on a front wall is level with it, never tilted against it.
- **persp-6 — Invariant: every protruding feature on a house shows its depth along that house's
  one oblique direction** (see "Each house's depth direction" below): window frames, the door
  surround, sills, flower boxes. All its visible side faces are on the same side and slant at the
  same angle. A sill's or box's top and its end (`oblique`: every edge level, plumb or along the
  offset) sit between its back and its front, and so do a frame's side face and reveal.

Which face is which, from how the walls are drawn: every house's walls, gables, roofs (their ridges
and eaves run across the picture), trims, windows, doors, chimney fronts and foundations are front
faces. The side walls beside the fronts (red, yellow, teal, pink, blue and the far houses) are drawn
as upright rectangles with level tops, so they are front faces too, set back. The side faces are the
near houses' step risers (each near house's two steps run sideways down toward the street), the
chimneys' sides (blue, far salmon, far yellow); the steps' treads are horizontal surfaces; the sills'
and flower boxes' tops and ends, and the frames' side faces and reveals that show their depth, are
`oblique` faces (persp-6). The steps' end toward the viewer
(`steps-side`) is a front face, and the far houses' and the pink house's steps, seen from the front,
are front faces.

How the geometry meets them (`env_shapes.py`, the "House perspective" pass; see
`review/house-perspective-before-after.png`). The measured shapes stay as measured; the pass redraws
the faces painted at stray angles, each still measured where the original shows it (`src`), so no
colour changes.

- **Levelled:** every trim band and its shadow, each at the mean of its old ends (the green house's,
  Derek's strike, now runs level from y 546.5 to 580.5; the red house's at its gable's foot, y 540);
  the roof ridges (red, teal, yellow and pink; far salmon, rose, pink and yellow) and the teal roof's
  eave; the green roof's shingle shades; the red skylight; the gable windows (red, blue, green:
  square, no longer skewed); the barge boards' and soffits' end cuts.
- **Sills and flower boxes** (`sill_box()`): see "Window sills and flower boxes" below.
- **Steps** (`persp_steps()`): each near house's two steps are rebuilt from the original's profile
  (its wall-side end, the two risers, the treads' tops and the foot, centred on the door): the
  profile level and plumb, the treads and risers receding to the steps' back by one depth ratio per
  house (red, yellow and green 0.9, teal 0.94, blue 0.933). The yellow house's wavy steps become two
  steps like the others, its landing the first. The paths and mailboxes follow by the street layout
  rules, which still hold.
- **Foundation:** the yellow house's front foundation, painted as a slanted strip, is a level band
  under its front wall.

What stays imperfect: the near steps still run sideways toward the street, as the original draws
them, so their profile stands about in the wall's plane rather than in front of the door; and the
side walls read as set-back front walls, where a true view down the street would show them receding.

### Window sills and flower boxes

Derek: "did you check all the houses and all the windows? The right green house flower box looks
wrong, the same way the left red house looks off." The previous pass built each box's front as its
back scaled about the vanishing point. Far from the vanishing point that scaling moves a point
almost straight sideways, so the red and green houses' boxes slid 20-40 px off their windows: the
green house's left box ran into the door surround, the others floated detached and skewed. The
check then tested only each edge's angle, never that a box belongs to its window. The red house's
left window glass had also turned grey: its colour was measured on the few pixels of glass the
near tree leaves showing.

> **How the spec is changing (#841).** It used to say a box's front is its back brought nearer,
> scaled about the vanishing point (persp-6), and that each box's back is centred under its
> window. It now says each sill and box is attached to its own window (its back on the frame's
> bottom, centred, a small equal overhang, never reaching a door or another window), its depth is
> one small fixed oblique offset scaled by the house's door, every flower box has the same
> proportions and shading, and glass keeps its glass colour where something stands in front of
> it. Why: a true perspective depth is right only next to the vanishing point; at the picture's
> edges it reads as a box sliding off its window, which is what Derek saw, and the original paints
> every box as a near-rectangular front with a thin top and a small darker end wherever it is.

How depth is drawn: **a fixed oblique offset along the house's own depth direction, not a
perspective scale.** Each box's front is its back moved by `(HOUSE_DEPTH x OFFSET_X, OFFSET_Y)` =
(±0.065, 0.01) door widths for a flower box and half that for a plain sill: sideways the way its
house's frames show their depth (below), and a little down. The house's own door is its scale, so a
near house's box shows a thicker top and end than a far one's, but every box shows the same shape:
a rectangular front, a thin lighter top and a small darker end on the same side as its window
frame's and door surround's side faces. A true one-point perspective depth was tried (an earlier
pass) and rejected for the reason above; an offset that changes direction with each box's position
would make neighbouring boxes on one wall disagree.

#### Each house's depth direction

Derek, on the pass above: "They still don't have the right angles that match the windows." Each
window frame and door surround already shows its own depth: it stands proud of the wall with a
darker side strip on one side, and a darker reveal runs down the inner side of the opening next to
the glass or panel, on the other. The boxes went the opposite way: on the green house the frames
and door surround show their side face on the right, and so do the original's boxes, but ours
showed their end on the left; on the red house the frames show theirs on the left and ours showed
the boxes' end on the right. Their tops also slanted at 35°, where the frames' depth edges run
level.

> **How the spec is changing (#841).** It used to say a sill's or box's front moves sideways *away
> from* the street's vanishing point (and 0.045 door widths down), so its darker end faces the
> vanishing point, on every house of that side. It now says each house has one depth direction,
> measured from its own frames and door surround, and every protruding feature on it (frames, door
> surround, sills, flower boxes) shows its depth along that one oblique: all its side faces on the
> same side, every depth edge at the same angle (8.7° below level: 0.065 across, 0.01 down per door
> width). Why: Derek saw that the boxes "don't have the right angles that match the windows": the
> frames above them, and the original's boxes, show their side faces on the other side and level.

Measured on the geometry (HEAD 2fb46c2, `FRAME_DEPTH` in `env_shapes.py`) and on the original

frame's own side beside its front, a reveal the opening's inner side; "w" is its width, in px and
door widths (dw), the size of its depth for that much protrusion. The depth direction is the way a
feature's front moves as it comes out of the wall; its side faces show on the other side.

- **win-7 — Invariant: every protruding feature on a house shows its depth along that house's one
  oblique** (`HOUSE_DEPTH`, persp-6). Every frame side face, reveal, sill and box: its depth vector
  (front minus back: a side face's top edge, a reveal's bottom edge, a sill's or box's offset) goes
  the house's way and slants at the same angle (within 1°); a frame's side face sits on the side
  away from that direction and a reveal on the side toward it; a sill's or box's end faces show on
  the same side as the frames' side faces. A box's end face is a parallelogram whose slanted edges
  are parallel to the frames' depth edges.

- **win-1 — Invariant: a window's sill or flower box is attached to that window.** Its back top
  edge lies on the window frame's bottom edge (within 1 px).
- **win-2 — Invariant: it is centred on its window** (within 0.5 px) **with a small equal overhang
  on each side**: `OVERHANG_K` = 0.04 door widths, and the whole sill or box, front included,
  stays within that overhang plus its offset of the frame's sides.
- **win-3 — Invariant: a sill or box never reaches a door, a door surround or another window**: no
  face of it overlaps any door face (frame, side, panel, reveal) or any other window's faces.
- **win-4 — Invariant: a box's depth is shown only by its top face and one end face, by one small
  offset**: the same `(OFFSET_X, OFFSET_Y)` door widths for every flower box, and half of it for
  every sill (the offset in proportion to how far it stands out), on every house, its sideways part
  the house's depth direction (win-7). Never a large scale about the vanishing point.
- **win-5 — Invariant: every flower box on every house has the same proportions and shading**: its
  sill band `BOX_CAP_K` = 0.09 and its box `BOX_H_K` = 0.2 door widths tall; one front colour,
  measured where the original shows that box's front plainly lit (`at=`), for its band and its box;

  plain sill's top and end shade its front by the same factors.
- **win-6 — Invariant: window glass stays its glass colour where something is drawn in front of

  from the same house's other window, not from the few pixels the original leaves showing.

## The traced environment (`--env traced`)

The previous version, kept for reference: every object cut out of the original and
vector-traced (`trace_env.py`). The rest of this section describes it.

### How the environment is traced

1. **Objects.** `OBJECTS` in `trace_env.py` lists every object back to front (in layer
   order), each with a rough shape: the matching hand-built object where that was drawn
   accurately (the near houses, the clouds), otherwise a polygon, ellipse or rectangle read
   off the original (trees, bushes, mailboxes, fences, flowers, toys, far houses). The
   street is fitted geometry: the road and lawn edges were measured on the original's
   unhidden stretches, and the kerb is two strips (face and shadow line) along each road
   edge.
2. **Cut-out.** A watershed on the original, seeded with each object's rough shape (shrunk
   so the seed is surely the object; for trees and props only pixels that differ from the
   background around them) and with the sky, snaps every object to the original's colour
   edges. The dogs (and the small puppy), their shadows, the title with its drop shadow and
   the corner sparkle are a separate label that is never traced.
3. **Occlusion.** Each object's full shape is what the original shows of it, plus what of
   its rough shape is hidden by something drawn above it — a dog, the title, or a nearer
   object (a wall behind a tree or a mailbox, a lawn behind a bush). Hidden parts are
   filled from the object's own visible pixels: walls, roofs, trees, clouds with a smooth
   push-pull (membrane) fill; the ground with its own **row-by-row gradient** (the road
   darkens toward the viewer row by row), and fringes of off-colour ground right next to a
   dog (soft shadow edges, stray fur) are refilled too. So under the dogs there is plain
   road, kerb and sidewalk, behind the title there is sky and the tops of houses and trees,
   and no layer has a dog- or title-shaped hole (`review/env-only.png`). An object that
   stands behind something lower in the stack (a tree behind a house) is never completed
   over it.
4. **Hand-built faces.** Where the original hides most of something made of clean
   geometric faces, a traced completion reads as a ragged patch, so it is drawn as flat
   faces instead (polygons measured on the original, `STEPS` and `CLOUDS` in `trace_env.py`),
   each coloured with a gradient fitted to what the original shows of that face:
   - the yellow house's **foundation, front steps and front path** (behind the puppy and the
     corgi's ear) are drawn over the traced house; under them house-yellow has nothing else;
   - the **two clouds behind the title** are voxel blocks like the original's other clouds —
     a frontal face, the side face turned toward the street's vanishing point (lit white on
     the sun's side) and the underside — drawn only as faces. Their colour is solved as a
     translucent material (80 % over the fitted sky and sun glow), so the sky shows through as
     in the original; the right cloud's underside, which the title hides entirely, takes its
     material from cloud-top-mid's underside (the cloud on the same side of the sun).
5. **Clean-up of edges.**
   - *Far street:* far objects in the haze give sky-coloured pixels joined to the sky back
     to it (compared with the sky right around them), lose slivers and detached crumbs of a
     neighbour, and far trees get a smoothed outline. Right under the title on the far right
     (`TITLE_TIGHT`) the title hides only its letters, not its soft drop shadow, so the far
     tree's crown and the far yellow house's chimney cap are traced as the original shows
     them instead of being completed with a guessed shape.
   - *Clips* (`CLIPS`): the tree by the yellow house is cut to its canopy edge and trunk (no
     slivers of yellow wall, no grass rim round the trunk), the green house to its roof's outer
     edge and wall (the blue house's roof and chimney, with the sky between them, are the blue
     house's), the yellow house's fence to where the steps begin, and one far tree loses a
     strip of the house beside it. The band just inside a clip is refilled from the object's
     interior, so no anti-aliased rim of the neighbour's colour is traced.
   - *Plain ground* (`PLAIN`): the lawn below the yellow house's steps and beside the puppy
     is plain gradient (traced detail there was only specks off the puppy's edge).
6. **Trace.** Per object: crop, upscale (to about 1,600 px on the long side), flatten with
   mean-shift, quantize to a small palette (deterministic k-means in Lab, 5–16 colours by
   size), fold anti-aliasing colours, smooth, and trace every colour with VTracer as a
   stacked layer (each shape runs under the next, so no seams). Ground objects (road,
   sidewalks, lawns) are a fitted vertical gradient with only what stands out from it
   (front paths, grass tufts, kerb lines) traced on top; the hidden ground is plain gradient.
   The gradient is measured only on the ground the original shows, from each row's main
   colour; a row that shows mostly something else (a front path crossing the lawn) is
   left to the rows around it, so the lawn under a dog is lawn green, not a path-grey mix.

## Dogs (`scene/dog-*`, `dogs/`)

The five dogs are **vector-traced from the original art** (`trace_dogs.py`), so they keep
its fur tufts, shading, expressions and proportions, while still being clean, isolated,
transparent vector layers. (A first, hand-drawn version — smooth spline shapes in
`build_dogs.py` — lost too much of the original's character; it is kept, see below.)

### How the dogs are traced

1. **Cut out each dog with a precise mask.** The hand-drawn silhouettes give a rough
   region per dog. Inside it the dog is separated from the street in one of two ways:
   for the golden retriever and the dalmatian, whose dark outline is unbroken, the
   background is flooded in from outside until it meets the outline colour; for the
   corgi, the schnauzer and the puppy (broken or fringed outlines, or outline colours close
   to the road's), GrabCut seeded from the silhouette, then grown out to take in the
   adjoining outline and with street-coloured pockets (road seen between legs) dropped.
   Dogs are cut front to back and each one is removed from the dogs behind it, so no
   road, grass or neighbouring-dog pixels leak in. Pinholes under 40 px are filled; one
   hand-placed fix (`fixes` in `DOGS`) removes a speck of pale ground seen between the
   golden's ear and the schnauzer's back.
2. **Upscale and flatten.** The crop is upscaled 4× (8× for the small puppy; Lanczos), its painted texture
   flattened with mean-shift filtering, and its colours quantized to a palette of 14–18
   colours per dog (deterministic k-means in Lab). Colours that exist only as anti-aliased
   fringes between two others are folded into their neighbours, and a 1.5 px band along
   the silhouette edge is drawn as outline (0.6 px for the small puppy), so no road colour
   survives at the edge.
3. **Trace.** The label map is smoothed (blurred one-hot), then each colour is traced with
   VTracer as a stacked layer: each layer is the union of its colour and all colours
   above it, so shapes overlap rather than leaving hairline seams. Paths are written in
   the original's pixel space.
4. **Group by colour family** — every colour joins the named family whose reference
   colour is nearest (table `DOGS` in `trace_dogs.py`).
5. **Occlusion.** Where a dog stands behind another, its shape runs up to 4 px under the
   front dog (so no gap opens between them) and no outline is drawn along that edge. The
   schnauzer's rump and far hind leg are hidden behind the golden retriever: they are
   **completed by hand** (`HIDDEN`, group `dog-schnauzer-hidden`) in the traced colours and
   clipped to the golden's silhouette, so they show only in the standalone schnauzer and
   never change the composite. No other dog is covered.
6. **Shadows** are traced from the original's own road shadows: pixels clearly darker and
   more purple than the rebuilt street under them (darker green on the lawn under the
   puppy), cleaned, carried a little under the feet, and given the opacity that darkens
   the ground as much as the original's shadow does.
