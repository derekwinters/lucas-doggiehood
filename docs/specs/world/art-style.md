# Art & UI Style

*Issues: [#64](https://github.com/derekwinters/lucas-doggiehood/issues/64) (world/house style), [#65](https://github.com/derekwinters/lucas-doggiehood/issues/65) (UI chrome)*

The house and world palette below is implemented: the neighborhood renders real [Kenney City Kit Suburban](https://kenney.nl/assets/city-kit-suburban) (CC0) models, staged under `Assets/Art/Houses/CityKitSuburban/`. The UI chrome direction ("Candy Cottage") is still a decided-but-not-yet-implemented spec for the components listed below.

## Color palette

**Bright & saturated.** Bold, punchy colors that read clearly at a distance and skew playful rather than naturalistic — not the muted/earthy or soft-pastel alternatives that were considered. ([#64](https://github.com/derekwinters/lucas-doggiehood/issues/64))

Environment surfaces (grass, street, sidewalk, crosswalk) carry this palette as hex constants on `Doggiehood.Core.Art.Palette`. Dog coats carry it as per-breed hex data. Houses carry it through the kit's own hand-painted textures (below), not through Core-owned hex color data.

## House architecture

**Real kit models, one per house, painted with the kit's own texture variants.** Each of the 4 starting houses ([World & Neighborhood](world.md)) renders as one of the 21 Kenney City Kit Suburban house meshes — chosen so no two starting houses share a model — giving each dog's home its own silhouette, rather than a uniform tract-house look. ([#64](https://github.com/derekwinters/lucas-doggiehood/issues/64))

Per-house color comes from swapping in one of the kit's own hand-painted texture variants (`colormap` — the kit's default — plus `variation-a`/`variation-b`/`variation-c`) as the model's main texture, rather than from procedural roof/porch geometry or Core-owned hex colors. `Doggiehood.Core.Art.HouseStyleTable` is the single source of truth for both which model (`HouseStyle.ModelName`) and which texture variant (`HouseStyle.TintVariant`) each starting house gets; `WorldBuilder.BuildHouseModel` applies the tint by cloning the model's renderer materials and setting `.mainTexture` to the loaded variant texture — a real texture swap, since the kit's variant textures are distinct hand-painted alternates, not a white base meant to be color-multiplied. The specific 4 model letters assigned are r/h/k/q: the Level-1 (as-built) mesh of each house's proposed [#59](https://github.com/derekwinters/lucas-doggiehood/issues/59) upgrade path, so homes start small and visibly grow as they level up. This is Derek's call (2026-07-25) resolving the earlier placeholder picks flagged in [#122](https://github.com/derekwinters/lucas-doggiehood/issues/122); each house keeps its original tint variant (the tint is independent of the model). The per-house front-door anchors for the new starters r/h/q are provisional placeholders (centered on X, toward the street) pending a gallery authoring pass, unlike the door data for the retained meshes, which is authored. Swapping which of the 21 letters is used is a config change to `HouseStyleTable`, not a rebuild.

Because r/h/k/q are each house's *Level-1* mesh, upgrading a house ([#59](https://github.com/derekwinters/lucas-doggiehood/issues/59)) swaps in the next rung of its per-house model ladder — the full L1→L4 ladders and their "anchored on L1" rule live in [Neighborhood Expansion → House leveling](../expansion.md#house-leveling), backed by `Doggiehood.Core.Art.HouseLevelModelTable`. As of the v0.6 de-graybox pass every rung has a full `HouseModelCatalog` entry, so all four levels render their chosen kit mesh at the fixed uniform `HousePlacement.KitScale` — a house visibly grows as it levels up while every ladder mesh still fits the shared lot envelope (no per-model normalization, no lot resize). The only thing still deferred is the door anchor of each non-L1 ladder mesh (and the r/h/q L1 starters), which stays a provisional placeholder pending a gallery authoring pass; the models are final. The graybox fallback remains only for a genuinely-unknown mesh (e.g. an expansion house with no ladder).

**Zone-built houses get a rolled look, not a fixed one ([#299](https://github.com/derekwinters/lucas-doggiehood/issues/299)).** The 4 starters above have hand-picked ladders and tints; every house the player builds on an unlocked zone lot (id ≥ 5) instead **rolls its own** — one of **five** model ladders and one of a **generated 20-color palette** of tints — settled by Derek (2026-07-28). The roll happens **when the zone unlocks** (the lot first appears), not lazily at build time ([#434](https://github.com/derekwinters/lucas-doggiehood/issues/434), moving #299's original build-time timing earlier), so the empty lot already knows the house that will stand on it — driving its house-sized foundation footprint and pre-placed yard trees (see the [#57 build note](../expansion.md#the-loop)). The five ladders are the four starter ladders plus a new 5th ladder (`HouseLevelModelTable` id key 5, size-ordered L1→L4 `o → p → a → m`, all catalogued via [#348](https://github.com/derekwinters/lucas-doggiehood/issues/348)). The pick is a **deterministic seeded RNG keyed on the house id** (`Doggiehood.Core.Art.HouseVariantAssignment`), so it's stable across sessions and iteration order, **assigned once** at `GameState.TryUnlockNextZone` (stored in `GameState.AssignedLotVariants`; `TryBuildHouse` reads that pre-assignment, falling back to the deterministic `HouseVariantAssignment.ForHouse` roll for a legacy save with no persisted entry) and **persisted** (ladder id + tint *index*) through `SaveCodec` — a `lotvariant=` line for an assigned-but-unbuilt lot, or the `house=` line once built — so it survives relaunch and the house's L1→L4 upgrades — leveling swaps the mesh within the rolled ladder, never re-rolls. The tint palette is a **curated, hand-picked 20-entry list** (`Palette.HouseTintHex`), settled by Derek & Lucas (2026-08-02, [#519](https://github.com/derekwinters/lucas-doggiehood/issues/519)) after an earlier generated even-18°-hue / fixed `S = 0.70`, `V = 0.90` rule produced an unpleasant electric violet/blue: 10 slots are kept from those generated values and the 10 flagged (electric) ones are softened — mostly desaturated, with the cool blues/violets nudged lighter. It stays **index-stable** at 20 entries, and each house stores its tint **index** (0–19), so the retune re-colors every existing house onto the approved palette for free with **no save migration**. Unlike the starters' `.mainTexture` variant swap, the tint is applied as a **material color-multiply** over the mesh (the same `ApplyVacancyTint` technique, via `WorldBuilder.ApplyPaletteTint`) — and the vacancy grey ([#58](https://github.com/derekwinters/lucas-doggiehood/issues/58)) still wins while the house is vacant, with the palette color showing on move-in.

The **placement, footprint, and fence** call sites resolve a zone house through that same rolled ladder ([#414](https://github.com/derekwinters/lucas-doggiehood/issues/414)). `HouseModelCatalog.ForHouse(houseId)` is the one zone-aware chokepoint: for a starter id (1–4) it resolves via `HouseStyleTable` as before, and for a zone id (≥ 5) it returns the rolled ladder's **level-1** mesh (`HouseVariantAssignment` → `HouseLevelModelTable.ForHouseLevel(ladderId, 1)` → `ForModel`) instead of throwing through `HouseStyleTable.ForHouse`. That keeps `HousePlacement.HouseFootprint`/`Position`, `LotFence`, and the yard/quest placement that reuses the footprint zone-safe once a zone lot has a front walkway — which it does once `WalkNetwork` spans zone tiles ([#398](https://github.com/derekwinters/lucas-doggiehood/issues/398)). These call sites carry only a `HouseLot` (no `house.Level`), and leveling never resizes or moves the lot (every ladder mesh fits the shared lot envelope), so the fixed level-1 footprint is a valid, level-invariant placement input; the rendered *visual* level is resolved separately from `house.Level` in `WorldBuilder.BuildHouse`.

When the kit model can't be loaded (an EditMode test seam, `WorldBuilder.ForcePrimitiveFallback`), houses fall back to a single plain graybox primitive with no per-house color or roof/porch detail — the graybox path exists to keep the world buildable/testable without the art assets, not to preserve the style spec on its own. A zone house with no rolled variant (an unknown expansion id, or one constructed directly in a test) likewise falls back to graybox.

## Delivery trucks

**Trucks carry standard car colors, assigned per-spawn ([#601](https://github.com/derekwinters/lucas-doggiehood/issues/601)).** A delivery truck renders the single Kenney Car Kit "delivery" mesh, tinted with one of a small **curated real-world car spread** — white, black, silver, gray, red, dark blue, dark green (`Palette.CarColorHex`, settled by Derek 2026-08-05) — so trucks aren't all identical. This is deliberately **not** the broad decorative 20-tint house table (`Palette.HouseTintHex`); it's the tight, believable spread of colors actual cars come in. The tint is applied the same way houses are — a **material color-multiply** over the model's renderers (`DeliveryTruckView` mirroring `WorldBuilder.ApplyPaletteTint`).

Unlike a house — whose tint is a **deterministic per-id roll** (`HouseVariantAssignment.ForHouse`) that `SaveCodec` **persists** — a truck is transient and never saved, so its color is picked **at spawn** from an incrementing spawn seed (`Doggiehood.Core.Art.CarColorAssignment`, a pure function of that seed so it stays unit-testable), and the pick **avoids the colors currently on the road** so two concurrent trucks don't look alike. Nothing about a truck's color survives its trip off-map; each new truck rolls fresh.

## Yard objects

**The backyard pool is a graybox placeholder ([#740](https://github.com/derekwinters/lucas-doggiehood/issues/740)).** A delivered `pool` gift renders as a two-part primitive — a gray open-topped shell with a blue interior surface inset within it and sitting slightly below the rim — sized from the rendered adult dog rather than from hand-picked meters, and coloured from named `Palette` entries (`PoolShellHex`, `PoolWaterHex`) the way `DecorationView` picks its graybox colours. It is a stand-in in the same spirit as the graybox yard decorations and the lost-item sphere: the real low-poly pool model is a separate art-asset task, like the [toy](https://github.com/derekwinters/lucas-doggiehood/issues/332)/[ball](https://github.com/derekwinters/lucas-doggiehood/issues/410) meshes. The placement rules and the yard-item invariant it obeys live in [World & Neighborhood → Backyard pool](world.md#backyard-pool).

## UI chrome direction: "Candy Cottage"

This section owns UI *style* only. UI **layout** — a screen's regions, anchors, and named size/margin constants — lives in the [UI Wireframes](../ui/index.md) section and follows the [UI Design Process](../../engineering/ui-design-process.md) (wireframe approved before any code). The style rules below are pulled forward as the shared baseline on [Shared UI Components](../ui/shared-components.md); every per-screen wireframe references them rather than restating them.

Thick dark outlines on all UI chrome, flat hard drop-shadows (no blur), chunky pill-shaped buttons and chips, bold rounded sans-serif type. A sticker-book feel, chosen specifically over a flatter "paper-craft" alternative for its legibility and match with the bright/saturated palette and low-poly toy-shelf look. ([#65](https://github.com/derekwinters/lucas-doggiehood/issues/65))

The "thick dark outline" is a **true constant-width contour stroke** — an even band that follows the rounded contour around every corner — not an offset-copy approximation, whose four shifted stamps read as uneven/flattened corners. See the [constant-width contour band](../ui/shared-components.md#outline-a-constant-width-contour-band-616) on Shared UI Components ([#616](https://github.com/derekwinters/lucas-doggiehood/issues/616)).

Applies to: the currency chip, the speech bubble indicator, the dialogue box, decoration/gift choice buttons, and should extend to menus/settings for consistency.

A reference mockup exists at [this artifact](https://claude.ai/code/artifact/e3f24c36-85e3-4301-a099-c16c8ecc47f0), showing both the chosen "Candy Cottage" direction and the rejected "Flat Paper-Craft" alternative for contrast.
