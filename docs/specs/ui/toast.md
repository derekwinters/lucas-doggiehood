*Wireframe issue: [#562](https://github.com/derekwinters/lucas-doggiehood/issues/562). Implements/covers: `ToastNotification`. Approved: Derek, 2026-08-04 ([`/approve` on #562](https://github.com/derekwinters/lucas-doggiehood/issues/562#issuecomment-5185675524)) — authoritative layout contract.*
*Mockup: [mockups/toast.html](mockups/toast.html).*
*Status: **implemented** ([#541](https://github.com/derekwinters/lucas-doggiehood/issues/541), third trigger added by [#675](https://github.com/derekwinters/lucas-doggiehood/issues/675)) — the engine-free single-slot `Doggiehood.Core.Ui.ToastQueue<T>` sequences requests; `Assets/Scripts/Unity/ToastView.cs` renders the current slot in the reserved top-left lane (IMGUI HUD element, mirroring the currency chip); and the three reward directors (`QuestCompletionDirector` off `QuestManager.QuestCompleted`, `OnboardingRewardDirector` off `OnboardingRewardChain.RewardGranted`, `MoveInToastDirector` off `QuestManager.MoveInOccurred`) assemble copy (`ToastCopy`) and enqueue. The one **debug** confirmation ([#692](https://github.com/derekwinters/lucas-doggiehood/issues/692)) enqueues the same way, from `SettingsPanel.ToastRequested` with copy in `BugReportCopy`. Wired in `WorldBootstrap`.*

## Purpose

A small, **non-modal** notification that slides into a reserved **top-left lane** to celebrate a completion the player just earned, then clears itself on a short auto-timeout (or the moment it is tapped). It is the standard "you did that, and here's your reward" surface for three — and only three — **reward** triggers: **quest completion** (`QuestManager.Complete`), **onboarding reward-chain step completion** (`OnboardingRewardChain.RewardGranted`), and a **move-in** (`QuestManager.MoveInOccurred`, [#675](https://github.com/derekwinters/lucas-doggiehood/issues/675)). It also carries exactly one **debug confirmation** — the [Settings Debug tab](settings.md)'s bug-report rows saying the snapshot was copied or saved ([#692](https://github.com/derekwinters/lucas-doggiehood/issues/692)) — which pays nothing and is reachable only behind the 10-tap Debug unlock. It is a HUD element like the [currency chip](hud.md), not a centered panel: it never dims the world, never blocks input, and mirrors the chip's reservation in the opposite corner. Reference resolution is 1920×1200 per [Overview](index.md).

> **How the spec is changing (#692).** This page used to say the toast serves **three — and only three — triggers**, every one of them a **payout** the player had just earned → it now names those three as the closed list of *reward* triggers and admits exactly one **non-reward** line beside them: the Debug tab's bug-report confirmation, which announces no coins → because [#692](https://github.com/derekwinters/lucas-doggiehood/issues/692)'s two rows have to tell the player the snapshot actually went somewhere, and inventing a second notification surface for one debug line would be worse than reusing this one. It is deliberately fenced: it is a **debug** affordance, gated behind the 10-tap Debug unlock, so a player who never unlocks Debug still sees only the three reward triggers. The component is reused **exactly as approved** — same pill, same lane, same one-line budget, same coin token (the token is fixed chrome; the debug line simply has no payout for it to illustrate) — so no new wireframe was needed. Adding a *fourth reward* trigger still needs the same deliberate change it always did.

> **How the spec is changing (#675).** This page used to say the toast serves *"two — and only two — triggers"*, both of them things the **player** did → it now serves **three**, the new one being a **move-in**: a household arriving and paying its 50 coins, which the player didn't directly do → because [#675](https://github.com/derekwinters/lucas-doggiehood/issues/675) made a move-in pay out, and a payout with no announcement is invisible. The count is still a closed list, not an open invitation: a fourth trigger needs the same deliberate change. The move-in reuses the approved component with new copy and no layout change, so it needed no new wireframe — but it did force a copy decision, below.

Deliberately **not** a centered modal. It replaces the modal-per-step [onboarding reward panel](onboarding-reward.md) for the reward-chain's completion feedback (reversing the #374 "brief modal celebration beat" exception — see [Notes](#notes)) with a lightweight toast that never interrupts play, while still sitting on the shared Candy Cottage baseline and reusing the [`CurrencyChip`](shared-components.md#currency-chip-currencychip) coin token.

## Regions

| Region | Contains | Shared component |
|---|---|---|
| Coin token | A leading gold coin, reusing the [`CurrencyChip`](shared-components.md#currency-chip-currencychip) coin-token treatment — all three *reward* triggers pay flat coins, so one icon covers them all; it is fixed chrome, so the one debug confirmation ([#692](https://github.com/derekwinters/lucas-doggiehood/issues/692)) shows it too with no payout to illustrate | [CurrencyChip](shared-components.md#currency-chip-currencychip) coin token |
| Message | One short dynamic line: the accomplishment + payout, one sentence. The pill grows to the measured text width up to `ToastMaxWidthPx`; the line **never wraps and never grows height** (`wordWrap` off), and any message that would still exceed the cap is **clipped at the pill edge** (`clipping = Clip`) as a fail-safe rather than bleeding past it. `ToastMaxWidthPx` is sized so every currently-approved line fits on one line at `ToastFontSizePx` ([#578](https://github.com/derekwinters/lucas-doggiehood/issues/578)) | Reuses the Candy Cottage baseline (cream pill, thick outline, hard shadow) from [Shared UI Components](shared-components.md) |
| *(no scrim, no button)* | The toast is the whole surface — no backdrop and no dedicated button; a tap anywhere on it dismisses early | — |

| `ToastCoinDiameterPx` | `60` | Coin token — matches [`CurrencyChip.CoinDiameterPx`](shared-components.md#currency-chip-currencychip) (#173) |

| `ToastAutoDismissSeconds` | `3.5` | Auto-timeout before it clears itself |
| `ToastSlideInMs` | `220` | Slide + fade in from the left edge |

The toast's **chrome** (cream pill fill, outline `OutlineThicknessPx` = 6, full pill radius `PillRadiusPx` = 999, hard drop-shadow `ShadowOffsetPx` = 8) and the **coin token** are owned by the [shared components](shared-components.md) ([#173](https://github.com/derekwinters/lucas-doggiehood/issues/173)) and not re-specified here. This page adds the toast-specific composition — the reserved lane, the single message line, the dismiss/queue timing — and sizes them.

## Per-toast copy — the three triggers

Every reward trigger renders one line: the accomplishment sentence followed by the flat coin payout as **"+N coins"**. The message is built in the thin Unity layer from Core-supplied data (the just-completed step/quest, or the arrived household, + amount); no copy lives in Core.

| Trigger | Copy |
|---|---|
| **Quest complete** (any completion path, `QuestManager.Complete`) | *"Quest complete! +N coins"* — N is the flat quest payout ([economy.md](../quests/economy.md), today 20) |
| **Onboarding — first quest** | *"You finished your first quest! +200 coins"* |
| **Onboarding — upgrade a house** | *"You made a house even nicer! +200 coins"* |
| **Onboarding — expand the map** | *"You opened up a brand-new street! +200 coins"* |
| **Onboarding — build a house** | *"You built a brand-new house! +200 coins"* |
| **Move-in — one dog** | *"Biscuit moved in! +50 coins"* |
| **Move-in — two dogs** | *"Biscuit & Pepper moved in! +50 coins"* |
| **Move-in — three or more dogs** | *"A new family moved in! +50 coins"* — no names |
| **Debug — bug report copied** ([#692](https://github.com/derekwinters/lucas-doggiehood/issues/692)) | *"Bug report copied (12.3 KB)"* — no payout; the size confirms the whole snapshot reached the clipboard |
| **Debug — bug report saved** ([#692](https://github.com/derekwinters/lucas-doggiehood/issues/692)) | *"Saved: bugreport-20260826-180411.txt"* — no payout; names the file to go and fetch. Terser than the copied line on purpose: with a full timestamped filename after it, *"Bug report saved: …"* measured **981 px** against the ~**934 px** budget, and the pill is not widened for copy ([#578](https://github.com/derekwinters/lucas-doggiehood/issues/578)/[#675](https://github.com/derekwinters/lucas-doggiehood/issues/675)). The filename itself starts with `bugreport`, so the shorter lead-in loses nothing |

One toast per **household**, never one per dog — the same per-household rule the [payout](../expansion.md#move-in-system) follows. A one- or two-dog household is named with the *same* name line the [welcome pop-up](welcome-popup.md) shows, so the two surfaces can never word a household differently.

**Why three dogs drops the names (Derek, 2026-08-08).** The message never wraps and clips at the pill edge, so every line has to fit the one-line budget at its **worst** case, not its typical one. Three names is the branch that doesn't: the roster's widest three ("Marshmallow, Cinnamon & Buttercup") plus the payout measures ~**1000 px** against the ~**934 px** budget, so it would have shipped clipping the reward amount for a 5%-probability household — invisible in casual playtest. Naming was dropped for that branch rather than widening `ToastMaxWidthPx`, which [#578](https://github.com/derekwinters/lucas-doggiehood/issues/578) sized deliberately. The branch is on *three or more*, so a larger household could never fall back to naming everyone. Measured worst cases at today's payout: one dog **589 px**, two dogs **810 px**, family line **584 px** — all inside the budget, and an EditMode guard derives each from the real name roster and re-measures with the real font rather than trusting these figures.

The four onboarding lines carry over **verbatim** from the retired [onboarding reward panel](onboarding-reward.md)'s accepted per-step copy (`/approve` [#374](https://github.com/derekwinters/lucas-doggiehood/issues/374)) — only the surface changes, not the words; the panel's separate **"+N coins"** button label folds into the one toast line. The onboarding amount is `OnboardingRewardChainNumbers.RewardPerStep` (200 today, [#674](https://github.com/derekwinters/lucas-doggiehood/issues/674)); the quest amount is the flat quest payout (20 today); the move-in amount is `EconomyNumbers.MoveInReward` (50 today, [#675](https://github.com/derekwinters/lucas-doggiehood/issues/675)). All three are read live, so the numbers in the table above are illustrations of the shipped values, not part of the approved wording. Keep every line to one short sentence that fits on a single line within `ToastMaxWidthPx` at `ToastFontSizePx` — an EditMode guard measures every approved line against the pill's text budget so new copy (or a wider `+N` payout) that would overflow fails loudly instead of clipping the reward amount ([#578](https://github.com/derekwinters/lucas-doggiehood/issues/578)). The two debug lines are measured by that same guard at their worst case — an absurd report size, and a full timestamped filename — and are **ASCII-only** like every other on-device label ([#291](https://github.com/derekwinters/lucas-doggiehood/issues/291)). The saved line was shortened to fit that budget rather than widening the pill, exactly as [#675](https://github.com/derekwinters/lucas-doggiehood/issues/675)'s three-dog branch was: measured worst cases are **561 px** copied and **769 px** saved.

## Notes

- **Not modal.** Unlike every centered panel in [shared components](shared-components.md#modal-overlays-block-all-input), the toast never registers with `ModalInputGate` and carries no backdrop — it is a HUD element like the currency chip, just tappable. World taps outside the reserved lane are unaffected; a tap *on* the toast only dismisses it and does not fall through to the world.
- **Dismiss model — both auto-timeout and tap.** The toast clears itself after `ToastAutoDismissSeconds`, and a tap anywhere on it dismisses early; either path runs the same `ToastSlideOutMs` exit. It can never trap the player (the same anti-soft-lock posture as the [confirmation dialog](confirmation-dialog.md) and [#329](https://github.com/derekwinters/lucas-doggiehood/issues/329)).
- **Sequential queue, one slot (`ToastQueueSlotCount` = 1).** Only one toast is ever visible. If a second trigger fires while one is showing — e.g. a quest-complete and the move-in it rolled, which land in the same frame — the second **waits** and plays immediately after the first's slide-out finishes, never stacked or overlapping. Order is first-come, first-served, so a move-in toast always follows the quest-complete toast that produced it.
- **Reverses #374's modal exception** (confirmed intended per [#541](https://github.com/derekwinters/lucas-doggiehood/issues/541)'s revise thread): the onboarding reward-chain step's completion feedback moves off the centered `OnboardingRewardPanel` (scrim + button) onto this toast. [onboarding-reward.md](onboarding-reward.md) and [onboarding.md](../onboarding.md#onboarding-reward-chain-316)'s reward-chain section are reconciled accordingly.
- **HUD reservation mirrors the chip.** [hud.md](hud.md) gains a **Toast lane** region, top-left, sized to `ToastHeightPx` + margins — nothing else renders there, the same posture as the [`CurrencyChip`](shared-components.md#currency-chip-currencychip)'s reserved top-right region.
- **Payout stays in Core.** The toast is pure presentation over the existing payout paths (`QuestManager.Complete` → `Wallet.Deposit`, `OnboardingRewardChain` → `Wallet.Deposit`, `GameState.HandleQuestCompleted` → `Wallet.Deposit` for a move-in); it shows the coins Core already granted and never moves coins itself. The currency chip updates on its own (it reads `Wallet.Coins` live). A reloaded chain never re-pays nor re-toasts, and the move-in reward is banked on the move-in itself — never on this toast or on the [welcome pop-up](welcome-popup.md), so dismissing either cannot cost the player the coins.
- **Reference resolution.** Constants are authored at the 1920×1200 (16:10) reference per [Overview](index.md); a Unity `CanvasScaler` scales from this so each px constant has a fixed meaning across tablet sizes.
- Style itself (outlines, flat shadows, pill shapes, rounded type, palette) lives in [Art & UI Style](../world/art-style.md); this page is layout only.
