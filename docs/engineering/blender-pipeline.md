# Blender Asset Pipeline

*Issues: [#774](https://github.com/derekwinters/lucas-doggiehood/issues/774) (this page), [#768](https://github.com/derekwinters/lucas-doggiehood/issues/768) (scripted authoring), [#775](https://github.com/derekwinters/lucas-doggiehood/issues/775) (one-command export), [#776](https://github.com/derekwinters/lucas-doggiehood/issues/776) (Unity import)*

The game's own 3D models (houses, trees, street props, and later toys, pools and dogs) are generated by **Blender Python scripts** checked into the repo. Nothing is hand-modelled. Claude writes and changes the scripts, Derek reviews the renders, and the exports are regenerated from the scripts with one command per set. This page describes the pipeline as it exists today under `art-source/blender/`. The step that brings an approved model into Unity does not exist yet and is marked **Open**.

What the models should look like is in the specs: [Art & UI Style → Art direction and Art budget](../specs/world/art-style.md#art-direction), [House Design](../specs/world/house-design.md) and [World Art](../specs/world/world-art.md).

## Where source lives

All model source lives in **`art-source/blender/`, outside `Assets/`**, so Unity never imports a script, a review render or an export that hasn't been approved for the game.

| Path | What it holds |
|---|---|
| `art-source/blender/` | The house kit: `dh_house_kit.py`, `dh_scene.py`, `base_house_1.py` … `base_house_10.py`, `piece_*.py`, the export and render scripts, `colour-schemes.json`, roof `textures/`, `exports/` and `review/` |
| `art-source/blender/environment/trees/` | The textured trees: generators, shared `textures/`, `exports/`, `review/` |
| `art-source/blender/environment/street-props/` | The street props: generators, shared `textures/`, `exports/`, `review/` |
| `art-source/blender/items/<item>/` | One folder per item (for example the chew bone, [#923](https://github.com/derekwinters/lucas-doggiehood/issues/923)): generator, `textures/`, `exports/`, `review/`, `tests/` |

Each folder has a `README.md` with its measurements, triangle counts and open concerns. Render scratch output goes to an `out/` folder, which `art-source/blender/.gitignore` ignores at any depth.

**Invariant — source art never lives under `Assets/`.** Only a model approved for the game is ever imported into `Assets/`, through the step marked Open below. A model kept as reference only stays in `art-source/` ([World Art](../specs/world/world-art.md)).

## Headless Blender

The scripts run Blender as a **Python module**, with no Blender install and no UI:

```
pip install bpy==5.3.0   # pinned; the scripts also use Pillow and numpy
python3 art-source/blender/export_houses.py art-source/blender/exports
```

`bpy` 5.3.0 bundles Blender 5.3 and its glTF exporter (Khronos glTF Blender I/O 5.3.x). Every script is run with plain `python3` from the repository root. The render scripts also need EEVEE to start headless; in a container without a GPU that means Mesa's software EGL (`libegl1`, `libgl1-mesa-dri`). The exports don't render, so they don't need it.

## Generator scripts and shared modules

Every model is built from scratch from named dimensions. There is no `.blend` file in the repo, and none is needed: a script is the source of truth.

- **`dh_house_kit.py`** is the shared kit: shared dimensions (slab, floor, wall, stud, rafter and trim sizes), the 12 colour schemes (`COLOR_SCHEMES`), `scheme_palette()`, a mesh builder, finished and framed walls, roofs, attach points, `tri_count()`, `export_glb()` and the render setup.
- **`base_house_N.py`** builds one base. Each exposes the same interface: `DIMS`, `NAME`, `RENDER_SCHEME`, `FRONT_Y`, `PIECES`, `attach_locations()` and `build("finished" | "framing", palette=…)`. Both modes come from the same `DIMS`, so the framing and finished versions line up exactly.
- **`piece_garage.py`, `piece_deck.py`, `piece_patio.py`** build the upgrade pieces, each from its own `DIMS`. The garage is the level-2 piece ([#780](https://github.com/derekwinters/lucas-doggiehood/issues/780), [#817](https://github.com/derekwinters/lucas-doggiehood/issues/817)). **`piece_addition.py`** is the superseded concept addition, kept for comparison; `dh_scene.py` still reads its `DIMS` to match each garage's ridge height.
- **`dh_scene.py`** fits the pieces to each base, builds the decorative driveway as its own object, and holds the level-4 placement rule used for the clearance tables.
- **Trees** (`environment/trees/`): `dh_tree_tex.py` paints the leaf atlases and bark maps; `dh_trees_tex.py` builds the trees. They reuse the branch helpers in `dh_env.py`.
- **Street props** (`environment/street-props/`): `dh_prop_tex.py` paints the surface textures and the label atlas; `dh_props.py` builds the props.
- **Items** (`items/<item>/`): `items/chew-bone/dh_chew_bone.py` builds the chew bone from one signed distance field, meshed with the dog kit's surface nets (`dogs/kit/dh_dog_mesh.py`), and paints its texture.

The environment scripts import the committed house kit by relative path (`../..` from `trees/`, and `../trees` plus `../..` from `street-props/`). No script imports a copy of another folder's modules.

**Determinism.** The generators seed their randomness (for example per tree name, or a fixed seed per texture), so the same script produces the same model every run.

## Conventions the models follow

- **Units:** 1 Blender unit = 1 m at in-game size. No scale factor is applied on export.
- **Axes:** in Blender the front faces −Y and up is +Z. The exporter converts to glTF's Y-up (`export_yup=True`), which puts the front at +Z. How that maps onto the game's model yaw is **Open** ([#776](https://github.com/derekwinters/lucas-doggiehood/issues/776)).
- **Transforms are applied on export** (`export_apply=True`).
- **Pivot:** a base pivots at the centre of its wall footprint on the ground; a piece pivots on its attach point; a tree or prop pivots on the ground at its trunk, post base or footprint centre.
- **Attach points** are empties named `ATTACH_<NAME>` (`ATTACH_ADDITION`, `ATTACH_DECK`, `ATTACH_PATIO`), parented to their mesh so they export as glTF nodes.
- **Object names:** `base_house_<N>_finished`, `base_house_<N>_framing`, `piece_<type>`, `tree_<kind>_<size>`, and the prop's key (for example `stop_sign`).
- **Material names** carry their set and slot: `DH_<Scheme>_<slot>` for houses (for example `DH_SageCottage_siding`), `DH_Tree_*` for trees, `DH_Prop_*` for props and `DH_Item_*` for items. A house paints only through its scheme's slots.

The final names in `Assets/` and in the Core part catalog are **Open** ([#775](https://github.com/derekwinters/lucas-doggiehood/issues/775), [#777](https://github.com/derekwinters/lucas-doggiehood/issues/777)).

## Export formats and commands

Everything exports as **glTF 2.0**. FBX is not used.

| Set | Command (from the repo root) | Writes |
|---|---|---|
| Houses | `python3 art-source/blender/export_houses.py art-source/blender/exports` | 64 `.glb` files: `base-NN-framing.glb`, `base-NN-level1.glb` … `level4.glb` and `driveway-base-NN.glb` for the 10 bases, plus `piece-garage.glb`, `piece-deck.glb`, `piece-patio.glb` and the superseded `piece-addition.glb` |
| Colour schemes | `python3 art-source/blender/export_colour_schemes.py` | `colour-schemes.json` |
| Trees | `python3 art-source/blender/environment/trees/export_trees_tex.py art-source/blender/environment/trees/exports` | 10 `.gltf` + `.bin` pairs and `trees_textured_stats.json` |
| Street props | `python3 art-source/blender/environment/street-props/export_props.py` | 26 `.gltf` + `.bin` pairs and `street_props_stats.json` |
| Chew bone | `python3 art-source/blender/items/chew-bone/export_chew_bone.py` | `chew_bone.gltf` + `.bin`, its two textures and `chew_bone_stats.json` |

**Houses** export as self-contained `.glb` files, each in its base's render scheme. A shingle or tile roof embeds the scheme's pre-tinted roof texture (`textures/roof_<style>_<HEX>.png`) with no `baseColorFactor`, so the roof carries one tint. Every other house surface is a flat material colour.

**Trees and street props** export as `.gltf` (JSON) + `.bin` with `export_keep_originals`, so the images are **not** embedded. Each `.gltf` references its textures by relative URI, `../textures/<name>.png`, and each texture is stored once for the whole set. Export into the set's own `exports/` folder, next to its `textures/`, or the relative URIs don't resolve.

**Checks the exports run.** The tree and prop exports read every written `.gltf` back and **exit non-zero** if a check fails:

- Every image URI is relative and resolves inside the set's `textures/` folder.
- Trees: every leaf material is `alphaMode: MASK` and `doubleSided`.
- Props: every textured material has both a colour and a normal map, and nothing is double-sided.

The house export has no checks yet. Checks for unapplied transforms, missing `ATTACH_*` empties, naming and triangle budget, and a single command that exports every set, are **Open** on [#775](https://github.com/derekwinters/lucas-doggiehood/issues/775).

**Invariant — every committed model is reproducible from its script in the repo.** Running a set's export command against a clean checkout rewrites its committed files byte for byte. This was verified with two runs of each export on `bpy` 5.3.0. A different `bpy` version can change the bytes, so it is pinned.

**Invariant — a textured set stores each texture once.** No `.gltf` embeds an image, and every image it references lives in its set's `textures/` folder.

## Textures

All textures are generated by the scripts with Pillow and numpy. No external images are used.

- **Houses:** the greyscale masks `roof_shingle_mask.png` and `roof_tile_mask.png` (made by `roof_mask()`), and a tinted copy per roof colour (`roof_<style>_<HEX>.png`, made on first use by `tinted_texture()`). The plan for Unity is one mask per roof style with the scheme colour as Base Color. How schemes are applied in Unity, including the roof, is **Open** ([#776](https://github.com/derekwinters/lucas-doggiehood/issues/776)).
- **Trees:** six 1024² leaf, blossom and needle atlases, plus three bark colour maps with their normal maps.
- **Street props:** five tileable colour + normal pairs, tinted per material by `baseColorFactor`, and a 2048² label atlas with its own normal map.

Rebuilding the tree and prop textures from their generators reproduces the committed PNGs byte for byte. Committed PNGs are the generators' own output with no added metadata chunks.

## Review renders

Each set has render scripts that draw the models at the game camera (orthographic, 45° pitch, yaw −40°), plus close-ups and line-ups for comparison. Examples are `render_base_1.py`, `render_bases.py` and `render_garage.py` for houses, `render_tree_closeup_tex.py` for trees, and `run_sampler.sh` and `render_street_props.py` for props. Each folder's README lists the full set.

Renders go to `out/` by default. Only the renders Derek approved are copied into the set's `review/` folder and committed. Renders are not byte-reproducible and are not covered by the reproducibility invariant.

## Triangle budget

Each export records triangle counts (`tri_count()` in the kit) in the set's stats JSON and README. The scripts do **not** check them against a limit.

The only enforced limit today is in Unity: `ArtBudget.MaxTrianglesPerMesh` (2,000), checked by the `LowPolyBudgetTests` EditMode sweep over the meshes under `Assets/Art`. Many approved models exceed it; the colonial is 2,672 triangles finished. It is being replaced by the per-scene [art budget](../specs/world/art-style.md#art-budget), whose values [#799](https://github.com/derekwinters/lucas-doggiehood/issues/799) sets after measuring on a phone. Until then the cap stays as it is, and no over-cap model can be imported.

## From an approved model to Unity — Open

No Blender model has reached `Assets/` yet. Open questions:

- **Where exports go in `Assets/`** and how they are named and loaded (for example under `Resources/` for load-by-name) — [#775](https://github.com/derekwinters/lucas-doggiehood/issues/775).
- **The glTF importer.** The project (Unity 6000.3) has no glTF import package in `Packages/manifest.json` today, and Unity doesn't import glTF without one — [#776](https://github.com/derekwinters/lucas-doggiehood/issues/776).
- **Import settings:** scale, axis and yaw, materials and scheme slots, double-sided alpha-clip leaves with coverage-preserving mipmaps, imported normals, read/write, and whether those settings live in committed `.meta` files. [Hand-Authoring Unity Serialized Assets](unity-serialization.md) currently says art model `.meta` files are *not* committed, so #776 has to reconcile that — [#776](https://github.com/derekwinters/lucas-doggiehood/issues/776).
- **A load check:** an EditMode test that every part in the Core catalog loads by name with its attach points — [#776](https://github.com/derekwinters/lucas-doggiehood/issues/776).
- **The art budget values** that imported models must meet — [#799](https://github.com/derekwinters/lucas-doggiehood/issues/799).
